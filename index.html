05 · Architecture

One transaction. Five handoffs.

The sequence makes the back-office story easy to follow in a classroom demonstration.

01Customer transactionAmount, payee, channel, location
02Java processingValidate and persist transaction
03Rule screeningThreshold + new payee check
04Python analysisHistorical average + std-dev score
05DBMS / fraud_flagStore decision for reviewers
06 · Technology

Three tools, one accountable story.

Each layer has one job, keeping the system easy to explain and extend.

J

Java

Real-time transaction processing and rule engine for validated input.

Py

Python

Anomaly score and statistical analysis using historical averages and standard deviation.

DB

DBMS / SQL

Transaction storage, integrity, fraud_flag, and the reviewer audit trail.

UI

HTML / CSS / JavaScript

Responsive frontend demo with live sample data and reviewer actions.

02

Early identification of unusual transactions

03

Reduced manual review workload

Reviewers can focus on the items that carry stronger signals.

04

Centralized records and prioritization

A stored flag and status preserve the reason and next action together.
